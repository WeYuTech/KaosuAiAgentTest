## 選取補問與狀態保護

- 同一 composer：`G2-選取AI更新條件-精靈.jpg`；「只看 MC38 今天的工單」經離線 Responses 工具替身呼叫真實 query endpoint。僅證明工具／狀態契約，不代表模型理解能力。
- 關閉補問：`G2-補問返回選取保留未送文字.jpg`；回 `guide-selection-ai`，保留捲動位置與「尚未送出的補問」，隱藏 composer 不可聚焦。
- 實際競爭拒絕：先準備上模卡，另一操作完工使資料改變，按確認得到 409；`G2-資料競爭明確拒絕.jpg`。返回重新核對後才成功，未自動重送。
- dirty、零、未填、保存失敗、pending、unknown、請求中／IME 延後切換：前端 122 項通過；後端 245 項通過、11 項環境條件跳過。這些為 DOM／HTTP 自動回歸；本階段沒有將真實 OS 輸入法或正式 SQL 斷線列為實操通過。

## 發現並修正的缺陷與證據版本

1. 單筆報工核對缺報工快照，離頁後失去舊不良原因：伺服器加入允許欄位的 `report_before`；新卡的移除原因顯示原值→0。早期修改報工截圖來自修正前已建立卡，不回填或改寫舊卡 digest；新卡由 HTTP／摘要測試驗證。
2. 隔離刪除影響工單誤列同排程全部工單：修正隔離範圍並重新預覽／確認；錯誤卡取消，保留失敗歷程。
3. 下模完成核對缺出站／完工連動：補齊真實 changes；早期下模截圖只顯示階段，最新摘要測試覆蓋連動。
4. 排程修改未呈現分配前值、重選同主檔清明細：加入白名單前值投影，相同候選只關閉；最新 `9549e2b` 畫面呈現 11→12、2→3、1→0 及未分配。
5. 翻頁未沿用 page_size／隱藏條件，預設 all 清暫選：合併已驗證條件、正規化語意；`2806e7a` 後實操跨頁通過。
