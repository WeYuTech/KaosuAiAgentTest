# WeYu 全系統 UI／UX 互動參考

這套資產是後續 UI 返工的固定呈現基準。範圍來自 PR #30（`43fab233567813ccae6931b76a05687d27048fc0`）的目前畫面盤點，包含 80 個可切換情境，以及 30 類既有使用者介面的映射。需求優先順序與交付門檻以引用本版本的 GitHub Issue 為準。

## 如何看範例

直接在瀏覽器開啟 `reference.html`。它不依賴網站部署、帳號、網路、模型或 MES；若環境不允許 `file:`，可在此目錄以靜態 HTTP 服務開啟。

```sh
python3 -m http.server 8090 --bind 127.0.0.1
```

然後開啟 `http://127.0.0.1:8090/reference.html`。

畫面上方「情境／外觀／重播」屬於範例控制列，**不屬於產品介面**。情境選單的 H、Q、N、F、P、B、W、U、R、A、C、X 編號對應 `scenarios.json`。情境可以直接重播；產品中的操作方式由「更多功能 → 介面設定」切換，兩種方式共用當前示範草稿。

建議先操作：

1. H01 輸入「你能幫我做什麼？」：首頁變成正常聊天室，三個模組是可選入口。
2. Q01 查看旋轉，再由 H02 按「查生產資料」，觀察等待、完成與停止。
3. F02 修改良品 → 介面設定切成精靈 → 核對 → 返回：內容與未送文字應保留。
4. P03 暫選資料 → 詢問 AI「只看 MC38」：新條件不應把舊暫選偷偷帶入；須重新選擇符合條件的資料。
5. P05 查看單筆報工並返回工單，區分父層返回與取消選取。
6. W09 查看結果未知：只查核既有操作，不能改數量重開送出。
7. U03 改推理強度，再核對前後值；U06 是一般使用者的只讀畫面。
8. R01 直接填表或展開選用的語句快填；核對返回保留選項。

## 視覺與互動設計

- 首頁只有一個可送出的輸入框與三個低強調捷徑。第一次送出後移除首頁 welcome 佔位，使用一致的訊息、等待與輸入區。
- 平面側欄只保留已釘選與最近聊天；封存、刪除、設定在更多功能。側欄拖曳即時跟隨，窄容器改成抽屜。
- 聊天＋作業單採左右分工；分步精靈採 650px 的內容最大寬度。目標摘要一處，真正可編輯的作業單一份。
- 候選列表以搜尋／篩選／分頁處理大量資料。查看明細、暫選、帶入是三個不同動作；窄版保留識別與動作，不塞超長 select。
- 主要按鈕跟隨階段：帶入作業 → 核對內容 → 確認送出。結果未知只提供查核；純查詢的停止不能冒充撤回 MES 寫入。
- 彈窗採短標題、必要一句、具體主動詞。進階說明按需展開；保存必要影響，不把安全資訊刪掉來換取短文案。
- 旋轉為 850ms linear infinite；內容進入 200ms、6px 位移；彈窗進入 190ms。降低動態偏好下停旋轉與位移，仍顯示狀態。拖曳不加寬度補間。
- 深色／淺色為本版的兩個主視覺。**產品既有三語、五外觀、版權資訊、浮窗、放大還原、嵌入與九個宿主 context 不能因範例簡化而移除。** 額外外觀沿用既有色彩辨識、套用同一字階／幾何／狀態；另依 Issue 驗收。

## 示意資料與實作邊界

**這是互動設計範例，不是 MES 實作，也不是正式站驗收證據。**

- 工單、數量、身分、費用、時間、核對期限與執行結果都是固定 fixture。範例的「完成」明示未寫入 MES。
- 24 筆本機資料、4 筆示範分頁、簡化關鍵字回覆、固定延遲、模擬保存與回執只為呈現狀態。產品必須接既有受限 AI／HTTP／server preview／確認與查核；不得把這些捷徑複製進正式程式。
- 範例使用簡化 DOM renderer；產品應延續 React、assistant-ui、Radix、Lucide、既有主題與狀態控制器。不能因範例重新渲染就重建 conversation／Guide、重播歷史訊息或丟失焦點／捲動。
- 全部業務合法性、候選是否可選、時間、原新值、影響工單與權限來自真實後端。範例不能取代 domain schema；模具無手填時間、排程 0 穴、未填／0、多原因、單筆報工 ID、整張完工連動仍按既有契約處理。
- 前一排程日報告是唯讀快照；重新作業要重新查詢目前 MES，不直接寫入快照資料。時區由 MES 來源提供，本 fixture 使用 UTC+07:00。
- 本版演示目前有入口的畫面。問題回報／主管審核及舊未掛載元件列在盤點的休眠清單，不新增入口或擴充後端範圍。
- 畫框高度、外層圓角、比較控制列是展示框架，不是固定產品視窗要求。產品依有效容器和軟鍵盤重排；複雜表單允許清楚捲動，不能縮字或刪欄位硬塞。

## 重建與檢查

`build-reference.cjs` 從 fragment 產生獨立 HTML，並內嵌安裝在 `CODEX_PRIMARY_RUNTIME_NODE_MODULES` 的官方 Lucide 圖示。原始圖示及 license 保留，沒有手繪圖示路徑。

`check-reference.cjs` 使用 Playwright 與 Chromium 擷取代表畫面；可用 `UX_REFERENCE_CHROME` 指定 Chromium。額外互動及窄版檢查的結果記錄於 `reference-qa.json`。

本套資產完成後固定至 Git commit。產品改完後仍須以最新產品 SHA，實際開啟瀏覽器操作，逐情境提交對照圖、正常速度錄影與狀態證據。只跑 build、單元測試或檢查 `overflow:false` 都不能當作 UI／UX 合格。
