# 生產情報助理 UI／UX 範例 v2（1:1 還原基準）

2026-11-03 經使用者確認，作為產品畫面 **1:1 還原**的唯一基準。來源是 PR #36 採用的原範例（設計提交 `8a837b6` 的 `docs/design/uiux-reference-20261102/`），外框換成使用者指定保留的四個產品元件，其餘全部照原範例。

## 保留的四個產品元件

| 位置 | 元件 |
|---|---|
| 左上 | 威友科技 logo＋「生產情報助理」 |
| 右上 | 操作紀錄、縮小視窗、更多功能、關閉 |
| 側欄底部 | 用量條（US$ 已用／上限） |
| 主畫面底部 | 版權列 `Corp. 2026 WeYu Technology Co., Ltd. All Rights Reserved.` |

## 照範例、從產品移除

- 作業標題列：一行作業名稱＋「聊天＋作業單／分步精靈」小標籤；角色與部門不放標題列。
- 「資料／紀錄」分頁與「AI 已設定」字樣。
- 新聊天與搜尋、收合在同一列。

## 範例本身的瑕疵（產品照修正後的樣子做）

1. 側欄項目一律靠左、同一縮排。
2. 側欄清單自己捲動，不被底部用量條蓋住。
3. 聊天內容底部留出輸入框高度，最後一則訊息能完整捲到輸入框上方。
4. 下模完成原範例漏了獨立確認，已補上，與產品卡控一致（依 PR #64 第 1 輪審查裁定）。

5. 模具四階段原範例未呈現真實卡控；依 PR #64 第 2 輪審查裁定，以 B08 fixture 同步階段原因與停用狀態，統一「清除換模紀錄…」入口及停用原因，並納入產品既有查詢歷史入口的文字按鈕呈現。

## 檔案

| 檔案 | 用途 |
|---|---|
| `reference.html` | 可離線開啟的互動範例；上方「情境／外觀／重播」是範例控制列，不屬於產品 |
| `reference-fragment.html` | 範例來源；以 `build-reference.cjs` 重建 `reference.html` |
| `scenarios.json` | 80 個情境的編號、群組、名稱與 key |
| `design-tokens.json` | 字階、間距、色彩與動態參數（沿用原範例） |
| `shots-1366/`、`shots-390/` | 每個情境在 1366×768 與 390 寬的標準截圖，檔名為 `情境編號-key.png` |
| `capture-reference.cjs` | 重拍標準截圖：`node capture-reference.cjs 1366`（以 `PLAYWRIGHT_CORE_PATH`、`CHROMIUM_PATH` 指定工具） |

範例資料（MC37、WO-261102-0382、P-102 外殼、陳先生等）都是固定示意資料，**不是 MES 實作**，不得把範例的捷徑或假資料寫進正式程式；產品驗收用的 fixture 放在 `tests/manual/`，內容對齊範例以利逐張比對。

## 例外：範例沒有的產品功能

範例早於 #44／#47，沒有「處理步驟面板」與分段輪詢的串流文字。這些功能保留，外觀改用本範例的色彩、字階與間距，並放在範例回覆訊息的同一位置。產品既有的三語、五種外觀、200% 縮放、iframe 嵌入與九個宿主 context 不能因範例簡化而移除。
