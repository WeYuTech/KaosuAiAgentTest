# 第二段：查詢與大量資料選取盤點

基準：main `36add62`；範圍為 #56 的 Q01–Q08、P01–P08，沿用 #54 畫面門檻。

## 既有流程與卡控

- `ChatQueryResults` 原本為訊息資料的唯讀投影，完整結果交由原查詢面板。明細展開只改本地呈現；帶入報工委派既有 `GuideHandle.beginReport`，不另建草稿或確認卡。
- `GuidedFlow.load` 沿用查詢版本、讀取世代、設備／日期／工單／品號／排序／歷史條件與分頁 API。查詢失敗或條件尚未送出時，帶入按鈕維持停用。
- 候選卡控仍使用 `canChooseRecord`、`moldStageAvailability`。不根據範例的合成狀態新增業務禁止規則。
- `RecordChoices` 的明細展開與 radio 暫選各自獨立；只有彈窗頁尾的帶入動作可交給 Guide。
- 修改／刪除報工先選工單，再選原 `REPORTS` 中的一筆；返回工單不建立新作業。
- 保存仍使用 Guide 版本與原串行保存；正式寫入仍經既有 proposal 與人工確認。
- #47 的開始請求、分段 GET 輪詢、原請求查核不變。#44 的處理步驟保留；停止等待不假裝成伺服器取消。
