## 第 1 輪審查修正

1. **等待狀態重複：已修正。** 轉圈與狀態文字本身就是步驟展開按鈕，預設收合，不再另列「處理中」框。展開只顯示原 HTTP `step` 事件；完成後自動收合為「已處理 X 秒 · N 個步驟」。骨架與停止查詢位置維持範例，原輪詢、停止與未知結果契約不變。
2. **候選分頁外框：已修正。** 工單及單筆報工的分頁均放在 `RecordChoices` 同一個圓角框中，分頁只保留內部上分隔線。補測外框底邊，1366 與 390 均通過。

## 實際修改

- 查詢等待、慢速、停止、失敗、空結果與縮小範圍按鈕對齊範例；保留原請求識別、#47 分段輪詢及 #44 處理步驟。
- 查詢結果以四筆預覽、欄位、明細及查看全部呈現；明細不修改草稿，帶入報工委派既有 Guide。人工報工與 IoT 分開，缺少資料不當成零。
- 候選彈窗的搜尋、設備、日期、分頁、明細、暫選列、AI 輸入及底部動作對齊範例。查看明細、暫選、帶入仍是三個動作。
- 單筆報工沿用工單內既有 `REPORTS`，提供本地搜尋與分頁、返回工單；不另建 API、資料庫或確認來源。
- 共用 Dialog 增加內容與頁尾之間的呈現插槽，AI 輸入仍使用同一份 App 文字；開關不重建 Guide。
- 修正實際操作發現的「帶入報工」互鎖：外層忙碌旗標曾令同一 Guide 拒絕動作；改由 Guide 管理處理狀態，保留防重入與情境版本檢查。

## 比對方法與保留功能

左範例、中產品、右差異疊圖；1366×768 與 390×810、深色、繁中、對齊資料。沿用第一段相同 Chromium 與灰階反鋸齒，範例只移除展示選單並對齊外框 viewport。每張都保留像素差異，沒有用遮罩藏起偏差。

量測包括標題、側欄項目、輸入框、查詢等待／慢速狀態與骨架、結果表頭與列、明細按鈕，以及彈窗搜尋、篩選、候選列、明細、分頁、暫選、AI 區、錯誤與底部按鈕。

範例未提供的既有產品功能仍保留：更多查詢條件（排序、範圍、工單與日期區間等）、#44 處理步驟、#47 分段顯示、長內容回到最新。單筆報工只能選目前工單已取得的紀錄，沒有假造跨設備查詢。未取得業務編號時以來源時間顯示，不把內部 SID 當成展示編號。原 API 卡控與確認契約不變。

## 發現與修正紀錄

- 第一輪發現查詢區雙重限寬、舊表格手機規則把明細列變成區塊、頁尾預設 margin、空狀態圖示尺寸及 AI 區外距；以計算樣式和實際 DOM 位置找出原因後修正。
- 新增按鈕一度缺少英／泰文翻譯，前端檢查有報錯；補齊後 176 項通過。
- 擴大量測曾發現 AI 區與輸入框偏移、候選分頁按鈕繼承錯誤字級；最終 5,850 項一致。
- 瀏覽器互動測試抓到帶入報工無動作，已修正並驗證經原 Guide 更新且不建立確認卡。
- 驗收腳本曾選到隱藏的父層報工列表，以及在選單關閉動畫完成前再次開啟；已改為明確選取目前子層及等待動畫完成，沒有用強制點擊略過問題。
