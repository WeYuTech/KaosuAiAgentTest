## 比較方式

每張圖依序為左範例、中產品、右差異疊圖。兩邊都使用無頭 Chromium、深色、繁中、同 viewport。單一像素任一 RGB 通道差異大於 16 時標紅，比例分母為整張應用畫面；此比例沒有被當作通過門檻。

## 尚未通過與契約邊界

1. 範例在能力問答、澄清等中立聊天也固定顯示「MC37 今日生產」及歷史選中列。現有 `GET /api/entry/{id}` 是未綁模組入口，沒有對應聊天室標題；依 ADR 005，交接才會建立／綁定作業。本次保留真實的「目前對話」，不硬編工單標題。這是**仍未通過的畫面差異**，不是准許例外。需要先確定中立聊天的命名／歸屬契約，不能在本輪前端自行假造資料。
2. 比較圖仍可見字型呈現、部分圖示與彈窗列細節差異；尚未得到逐項視覺放行。量測有超過 4px 的情境依表列為失敗，不能用整張比例低取代位置門檻。
3. C02 的長文字是透過 HTTP fixture 注入既有 Markdown 訊息元件，驗證捲動與排版，**不代表真的從首頁完成生產資料查詢**；正式唯讀查詢仍須原分類／交接流程。其回覆工具與範例底部內容仍有差異。
4. C01 額外處理步驟面板屬 #44／#47 的保留功能；其他差異不因此一起豁免。

## 重現與清理

先執行 `cd frontend && npm.cmd run build`，再從倉庫根目錄執行：

```powershell
node tests/manual/issue55-capture.cjs
node tests/manual/issue55-environment.cjs
node tests/manual/issue55-record.cjs
node tests/manual/issue55-video-check.cjs
```

fixture 僅位於 `tests/manual/`；每次建立獨立記憶體聊天資料、臨時 loopback HTTP 伺服器與無頭瀏覽器，於 finally 關閉。錄影轉檔使用本機既有 FFmpeg，不新增產品套件。固定設備、日期與回覆都是模擬資料，不包含金鑰、session 或正式資料庫內容。
