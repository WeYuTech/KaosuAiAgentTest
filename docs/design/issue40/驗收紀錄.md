# 第 40 項：系統狀態與稽核呈現

基準：main `3d4b6a5`。範圍限定 W、C、X、A；不修改後端端點、交易、確認雜湊、查核與權限規則。

## 既有契約盤點

- Guide 讀寫使用 `/api/conversations/{id}/guide`，版本不符回覆 409；前端保存佇列仍以伺服器版本為準。
- 核對使用既有 `/proposals`，確認仍核對操作者、摘要雜湊、期限、需求版本、資料狀態與寫入開關。
- 未知結果保留 `submission-recovery` 原操作標記，僅透過既有讀取／reconcile 查核，不重送確認。
- 401／403 仍隔離目前畫面與晚到請求。未送文字及未保存欄位改採原身分／聊天範圍的工作階段副本；重新讀取後必須比較，不能直接覆寫。
- 聊天 GET 沒有訊息提交識別或處理 token；查核只讀取既有紀錄，不能宣稱已確認原訊息送達，也不自動重送。
- 操作紀錄由 `/api/audit` 提供實際異動，個人統計沿用 `/api/conversations/statistics`，共用模型費用沿用 `/api/budget`。

## 證據與重現

- 固定範例：`8a837b644f552ac4a028bb4328bd78519b8c17c0`，實際在無頭瀏覽器切換 19 個情境。
- `paired/`：左為固定範例、右為產品。`product/390-W04.png`、`390-W09.png`、`390-X05.png` 為窄畫面。
- `fixture-A.mp4`：驗證、保存失敗、衝突、過期、重複確認、成功、拒絕、未知與關閉寫入。
- `fixture-B.mp4`：訊息未知、長回覆、登入與權限、連線、面板失敗、原操作、紀錄與統計。
- 錄影為正常速度，僅裁掉啟動段，沒有加速或跳接；H.264、yuv420p、faststart。每一段皆以新的 fixture DB 與獨立模擬預算帳本啟動。
- 所有故障、分類與資料控制程式僅在 `tests/manual/`；產品沒有測試開關。控制端點僅存在於隔離驗收伺服器，並以 loopback 啟動。

```powershell
npm.cmd --prefix frontend run build
node tests/manual/issue40_reference.cjs
node tests/manual/issue40_capture.cjs A
node tests/manual/issue40_capture.cjs B
node tests/manual/issue40_capture.cjs 390
```

Playwright 沿用既有安裝，路徑可用 `PLAYWRIGHT_CORE_PATH` 指定；瀏覽器備援可用 `CHROMIUM_PATH`，轉檔可用 `FFMPEG_PATH`，播放驗證可用 `BROWSER_PATH`。並行驗收時用不同的 `CAPTURE_PORT`。

## 與範例的必要差異及限制

- 單一真實 Guide 與確認卡沿用既有流程，沒有搬入範例腳本或假回執。衝突重套只帶回實際改動欄位，其他欄位保留伺服器最新值；目標不同不得重套。
- 未知結果不能重送；查核原訊息的現有 API 沒有獨立訊息提交識別，因此只讀回紀錄並保留未知提示，不把文字相同當成送達證明。
- 稽核設備透過同一使用者可讀的既有確認卡目標補足；沒有可讀來源時明示「紀錄未提供」，不推測設備或已完成異動。結果頁未取得可證明異動時不以預計異動替代。
- 本機未保存欄位為工作階段副本，依身分與聊天隔離且限 24 小時；重新載入時先核對最新版本，不自動覆寫。禁止瀏覽器儲存時仍可在當前畫面操作，但無法保證跨重新載入恢復。
- 本輪保留既有模式與宿主外框；390px 比較採緊湊雙欄，未知結果查核固定可見，統計以個人／共用兩區呈現。
