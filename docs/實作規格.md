# MES 對話操作助理規格

狀態：規格草案，依使用者已確認需求整理；原始碼與實際執行證據持續補齊。

## 問題與預期成果

現場人員須跨排程、報工與模具頁面查詢、選取及輸入。新助理嵌入既有 MES，沿用 Emerald.AI 的右下角入口與展開對話體驗，讓人員以自然語言完成原功能；所有寫入先呈現可核對的確認卡，明確同意後才執行。

## 使用者情境

1. 作為操作人員，我能先選排程、報工或模具上下模，避免操作錯模組。
2. 作為操作人員，我能核對可信登入身分，再選擇有權限的操作情境；選擇角色不會增加權限。
3. 作為操作人員，我能沿用目前頁面的設備、工單與排程，並在開始時核對。
4. 作為新手，我能點選聊天提示，理解各模組能做的事情。
5. 作為排程人員，我能依日期、設備、工單查詢、排序、換頁及展開明細。
6. 作為排程人員，我能挑選品號、模具、設備、工單與模穴，新增或修改排程。
7. 作為排程人員，我能設定起始時間、週期、目標模次、狀態、優先序及備註。
8. 作為排程人員，我能看到依 08:00 生產日切點計算的日期、結束時間及各列目標件數。
9. 作為報工人員，我能查詢執行中資料與歷史，看到單筆人工報工。
10. 作為報工人員，我能新增、修改與刪除人工良品及不良原因明細。
11. 作為報工人員，我能修改模穴數並核對實際影響目標。
12. 作為報工人員，我能對排程完工，且確認卡列出同排程所有受影響工單。
13. 作為報工人員，我能分辨人工良品、IoT 產量及 IoT 推算良品；未知不顯示成零。
14. 作為換模人員，我能依廠別、設備與模具查詢目前狀態及歷史。
15. 作為換模人員，我能選擇明確的候選排程，依序上模開始、上模完成、下模開始及下模完成。
16. 作為換模人員，我能清除歷史換模，確認卡須揭露四個模具時間及進出站時間的影響。
17. 作為操作人員，資料不足或目標有多筆時，助理會追問並保留已收集資料。
18. 作為操作人員，我能在確認前修改草稿或取消，取消不產生業務寫入。
19. 作為操作人員，刪除、完工與清除換模各自確認，不能被一句批次同意隱含執行。
20. 作為操作人員，確認過期、身分失效或資料被他人修改時，我會收到明確提示並重新核對。
21. 作為操作人員，重複點擊不會重複報工；執行結果未知時不會自動重送。
22. 作為管理人員，我能追查執行時間、操作者、模組、動作、結果與實際資料表欄位變化。
23. 作為管理人員，我能將錯誤回饋送審，審核修正知識後通過回歸案例才發佈。
24. 作為驗收者，我能在隔離資料中重演完整排程、報工、上下模情境，不影響正式 MES。

## 實作決策

- 新增 AI 協調後端與明確的操作契約，優先重用原 MES 查詢及命令 API。模型不直接執行 SQL、不指定任意 URL 或資料表。
- 現行 EPS 入口為排程 setup 新版、schedule_report 報工、mold 模具頁。隱藏舊功能與目前功能分開盤點；使用者要求的完工明確納入。
- 前端採 React／TypeScript，延續 Emerald.AI 的浮動入口、展開、模組入口、對話與確認卡體驗。後端採 Python／FastAPI，便於延續既有 Emerald 技術。
- 模型採 OpenAI Responses 的受限工具呼叫。預設候選 gpt-6.1-sol，正式選定前以帳戶可用模型及官方文件核對；費用累計上限 US$20。
- RAG 僅檢索已審核且有版本及來源的操作知識。業務卡控寫在程式與原 MES 後端；錯誤對話不直接變成新知識。
- 預設隔離模擬模式；正式連線使用可驗證的 MES 登入與權限。前端 localStorage、聊天自述身分及角色下拉選單均不當成授權證明。
- 草稿綁定操作者、模組、目標、完整參數、資料版本及到期時間。確認時重新驗證；成功前回讀必要資料。未知結果保留，不自動重送。
- 新增表一律使用 ZZ_AI_AGENT_OPERATION_ 前綴。簡單記錄操作、確認、結果、資料表主鍵與欄位前後值；預期變化與實際觀察分開。
- 原程式缺陷不照抄：小數截斷、IoT 空值顯示零、缺 await 的確認、錯誤時間映射、HTTP 200 當成功等均列入改善與測試。

## 驗收邊界草案

主要透過公開 HTTP API 驗證登入、對話、查詢、草稿、確認、執行結果及稽核；另以瀏覽器操作驗證三個入口、身分、追問與確認卡。測試不依賴私有函式或直接修改內部狀態。

逐一涵蓋正常生命週期、缺資料、歧義、原卡控、跨日、多人競爭、重複確認、逾時未知、權限與人工／IoT 數量區分。離線模型替身僅驗證流程；真實模型驗收另行標示，不能混稱。

## 工作切片草案

1. 可登入的模組入口與可信查詢：三入口、身分核對、建議提示、唯讀查詢、模擬環境及整合驗收。無前置。
2. 對話排程：收集資料、歧義選擇、計算預覽、人員確認、新增／修改、查回與追溯。依賴 1。
3. 對話報工：人工報工新增／改／刪、模穴、獨立完工確認、IoT 區分、查回與追溯。依賴 1。
4. 對話模具上下模：四階段、候選排程、廠別、歷史清除與獨立確認、查回與追溯。依賴 1。
5. 真實模型與知識修正：模型工具呼叫、已審核知識檢索、回饋送審、版本及費用追蹤，完整對話驗收。依賴 2、3、4。
6. MES 整合交付：可信登入接合、既有 API 契約驗證、嵌入產物、部署說明與端到端驗收報告。依賴 5。

## 範圍界線

不默默加入現行沒有的排程刪除、拖曳排程或其他製程功能。原程式沒有的限制與修正必須標示為新防護。正式資料不作試寫。原 API 若不能提供原子交易、可靠結果或權限檢查，須揭露限制並補足服務端介面，不能以提示詞假裝解決。
