# 模型選型與知識修正

## 本次選擇

採 Responses API 與 gpt-6.1-sol。Responses 提供對話與嚴格工具呼叫；模型讀取受限查詢，產生操作草稿，由應用後端建立確認卡。模型沒有「執行」或「同意」工具。

平台上的 Agents 是另一層代理建置與執行產品。本專案已使用既有 Emerald／MES 的前後端與身分，無須為了稱作 AI Agent 就另外使用 Agents 產品。Decisions 不在本次呼叫範圍。金鑰只需 Responses 權限，不需檔案上傳、向量庫、Realtime、圖片或微調權限。

依 2026-10-30 官方文件，gpt-6.1-sol 的工具呼叫使用 Responses API；輸入每百萬 token US$2，輸出 US$10。預設低推理量，降低現場等待時間。模型名稱與經核對的價格須一起更新，未核對新價格時程式拒絕付費呼叫。

來源：[模型規格](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[嚴格工具呼叫](https://developers.openai.com/api/docs/guides/function-calling)。

## RAG 放什麼

- 原 MES 操作名稱、選項、階段順序、確認範圍與已核實的連動。
- 人工良品與 IoT 推算量的解釋。
- 指向盤點文件、來源版本與核實過的修正。

第一版是本機文字檢索，以詞與中文字組排序，並按模組篩選；不是向量嵌入服務。知識規模目前很小，這樣容易追溯，也不需另建外部向量庫。實際工單、設備與當下狀態仍即時查詢；不把過時資料當知識文件答案。

## 操作出錯後如何改善

1. 操作者回報預期與實際結果，連結該次對話。回饋只進待審區，不進檢索結果。
2. 主管區分是知識說明、模型理解、資料主檔或後端程式錯誤。
3. 知識錯誤由主管提交修正文與來源；程式卡控錯誤須修程式及新增對應回歸案例。
4. 部署管理員提供具體案例，先跑固定 HTTP／CLI 回歸套件，再以真實 Responses 驗證隔離資料庫中的候選知識；失敗不發布。案例必須實際檢索到同一候選內容雜湊，模型結果也須列出該知識，且回答符合判準、沒有建立操作草稿。
5. 後續對話檢索已發佈版本，舊操作紀錄保留。發現修正有問題時，另提修正版本，不覆寫歷史。

這不是即時訓練，也不保證模型從一次錯誤後永不再犯。對話與回饋不能改寫權限、確認或 SQL 卡控；高風險連動由確定性的程式與交易驗證負責。

### 候選知識發布命令

建立 UTF-8 JSON，例如 `.local/knowledge-case.json`。`cases` 須有 1 至 20 筆，每筆都需問題及非空 `expected_contains` 字串陣列；`forbidden_contains` 可省略。以下範例應對應主管本次審核的人工／IoT 說明，其他候選須改成自己的問題與可核對判準。

```json
{
  "cases": [
    {
      "question": "人工報工與 IoT 推算數量如何呈現？",
      "expected_contains": ["人工", "IoT", "分開"],
      "forbidden_contains": ["合併為同一數量"]
    }
  ]
}
```

```powershell
.\.venv\Scripts\python.exe scripts/publish_knowledge.py --db .local/operations.db --case .local/knowledge-case.json -- <已審核回饋ID>
```

`--case` 不可省略，CLI 沒有跳過回歸或模型驗證的選項。驗證將原先全部已發布知識與候選複製到短期隔離 Store，查詢僅使用合成狀態；任何操作草稿請求立即拒絕。實際對話仍讀原資料庫，候選在所有案例通過前不可見。字串判準是必要的回歸條件，不能替代主管對知識正確性的審核。

發布前再次比對審核內容與既有知識集合；若驗證期間有變動就拒絕，需重新驗證。成功發布的 `regression` 收據記錄候選、案例、審核內容、既有知識集合的雜湊，以及每筆模型回答與檢索來源摘要的雜湊、固定套件結果摘要及模型名稱。測試使用注入模型邊界，不付費，收據會明示「非真實模型驗收」；管理員 CLI 預設才使用真實 Responses 與既有累計預算，沒有另開或歸零帳本。

## 費用與秘密

本次上限 US$20。每次呼叫先預留最壞估計費用，再依實際 token 結算；未收到用量時保留預留，不自動重試。帳本跨應用啟動存在，模型回放腳本也使用同一份帳本。

金鑰只放後端 `.env`，不放前端、Git 或一般操作紀錄。專用測試金鑰到期後需重新配置；用量頁與本機帳本可互相核對，快取折扣可能使平台實際費用較本機保守估算低。
