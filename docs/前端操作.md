前端位於 `frontend/`，以 React、TypeScript 與 Vite 建置。介面沿用既有 Emerald.AI 生產情報助理的黑白 Zinc 主題、原品牌圖、Inter Variable／IBM Plex Mono 字體、按鈕尺度、圓形啟動器與對話框行為；加入排程、報工、模具入口與作業確認內容。

## 啟動與建置

在 `frontend/` 執行 `npm ci`，再執行 `npm run dev`。開發站台預設為 `http://127.0.0.1:5173`，`/api` 代理到 `http://127.0.0.1:8000`。後端需另外啟動。

執行 `npm run typecheck` 進行 TypeScript 檢查；`npm test` 驗證根路徑／MES 子目錄的 API 對應與跨站阻擋；`npm run build` 會先檢查再產生 `frontend/dist/`。建置產物包含 SPA 與 `widget-loader.js`。正式整合應讓前端與後端 API 位於同源站台，登入資訊由後端 cookie／MES 登入橋接管理，不透過網址傳 token 或 API key。

## 使用流程

1. 點選右下角白色圓形 Bot「生產情報助理」。
2. 選擇生產排程、生產報工或模具上下模。
3. 模擬環境選擇生管人員、現場作業員、模具技術員或現場主管；也能沿用目前 session。模擬身分切換不能視為正式登入授權。
4. 使用建議提示或自行輸入需求。提示只帶入輸入框，不會自動送出或執行。
5. 「作業資料」可查看後端最新資料，選定一筆後會建立帶有該資料上下文的新對話。
6. AI 缺資料時會透過後端模型追問。前端不以關鍵字規則冒充自然語言解析。
7. 寫入前先核對確認卡的設備、工單、排程、人工良品、不良原因或模穴等業務資訊。完工等連動操作另列全部受影響工單與下一張排程開始時間。「查看資料異動明細」可展開完整資料表與欄位前後值。「同意並寫入」才送出確認。刪除、完工、清空類動作另需勾選獨立確認。
8. 取消或逾期的草稿不能直接寫入。待確認時可直接用自然語言修改草稿，舊卡會停止確認，補齊資料後生成新卡；畫面會顯示取代狀態。待確認時不切換資料或模組，避免確認對象混淆。
9. 成功後重新取得作業資料；「操作紀錄」顯示後端稽核內容。

作業資料可依設備、工單、日期或 `起日~迄日` 查詢，支援每頁 20／50／100 筆與前後頁。右下「回報問題與來源」可提交操作錯誤；回報會待人工審核，不直接變成已發布知識。同區可展開來源版本與 API 用量。

正式模式只顯示伺服器 `GET api/session` 回傳的可信登入身分，不提供模擬角色選擇，也不呼叫 demo 登入。模組入口依可信 roles 顯示可用狀態；未取得 MES 登入資訊時可重新確認登入。伺服器仍須對每個操作再次授權。

正式初次查詢會沿用宿主 URL 的設備與排程日期；未提供日期時使用健康狀態 API 的 `business_date`，不是瀏覽器所在時區的當日。現有 MES 來源已確認為 UTC+07:00；確認卡與頁腳顯示 MES 時區，確認卡若附 `business_timezone` 則優先使用。無時區的作業時間依 MES 顯示時間解讀，現場 08:00 換日邏輯由後端維持。宿主提供的執行主鍵／排程主鍵會作為固定上下文篩選帶入查詢，避免取得過大的全廠資料。若初次查詢遭範圍限制或失敗，仍可進入對話補條件，或到作業資料頁調整設備、日期與工單。模擬環境仍可從完整合成資料開始。

若確認卡的 `writes_enabled=false`，或正式模式沒有明確允許寫入，介面顯示「正式寫入尚未啟用」，停用同意按鈕，但保留查詢、草稿預覽與取消。預覽若附帶時間與新增識別碼政策，會在確認卡中說明：實際異動時間以執行時 MES 伺服器為準；新增識別碼在提交時配置，預覽值不是正式識別碼。

## 沒有模型時

`GET /api/health` 回傳 `model_configured=false` 時，介面清楚顯示「AI 尚未設定」，停用對話送出。仍可使用「結構化操作草稿」，依 `/api/capabilities` 的 JSON Schema 填寫欄位；這是人工表單，不是假 AI。表單呼叫 `POST /api/conversations/{id}/proposals` 建立確認卡，不直接寫入。陣列／物件欄位使用 JSON 輸入並由伺服器驗證。

## 嵌入既有 MES

將 `dist/` 與後端 API 反向代理佈署在原 MES 同源的 `/KSS_MES/ai-agent/`。頁面入口保留結尾斜線，或使用該目錄的 `index.html`。在 MES 頁面加入：

```html
<script defer src="/KSS_MES/ai-agent/widget-loader.js"
        data-assistant-url="/KSS_MES/ai-agent/"></script>
```

`data-assistant-url` 可省略，預設就是載入器所在目錄。載入器只接受與 MES 同源的目標，跨站設定會拒絕建立框架。助理的 API 依頁面目錄計算，例如上述頁面會請求 `/KSS_MES/ai-agent/api/session`，不會錯打站台根目錄 `/api/session`；Vite 靜態資產也採相對路徑。

原 ASP.NET cookie 若設定 Path 為 `/KSS_MES`，瀏覽器即可在同源 `/KSS_MES/ai-agent/api/` 請求中帶上，請反向代理保留原 cookie 與必要的驗證標頭。前端不讀取 HttpOnly cookie，也不自行交換或保存登入 token。

載入器以 Shadow DOM 隔離啟動按鈕，以 iframe 隔離助理與宿主 CSS。只從宿主網址帶入 OPERATION、SCHEDULE_DATE、執行主鍵、排程主鍵及 EQP_NO 白名單欄位。跨視窗訊息會檢查來源 origin 與 source。這些上下文僅是選取提示，授權與資料歸屬仍由伺服器驗證。

桌面預設右下角 400×500 小視窗，44px 圓形啟動器可開啟／收合。標頭的放大按鈕會填滿完整瀏覽器視窗，再按可還原小視窗；嵌入模式會同步放大宿主 iframe。手機採全螢幕面板。Esc 收合、Tab 循序移動、Enter 送出、Shift+Enter 換行。繁體中文輸入法組字時 Enter 不會送出。支援 reduced-motion、可見焦點與錯誤／成功狀態播報。

## 範圍與限制

前端不存 API key、不呼叫 SQL Server，也不自行推導正式權限。API 錯誤會保留輸入或確認卡供查明，不在網路失敗時自動重送寫入。查詢、確認卡、操作紀錄皆來自後端；人工報工與 IoT 量依來源欄位各自顯示。正式站台登入橋接與業務交易可靠性需由後端部署及驗收共同確認。
