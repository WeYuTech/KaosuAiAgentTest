# ADR 004：管理設定與定時唯讀報告

日期：2026-11-01。狀態：採用。來源：使用者明確要求納入 API／Agent 設定、額度調整與定時報告，同時保留 US$20 上限及既有權限。

## 權限與設定

沿用既有 `review` 主管權限調整全域非機密模型設定及額度，其他已登入者唯讀。正式權限仍來自 MES 帳號與部署 allowlist，不接受前端自稱主管，也不新增 ADMINV2 特例。

來源的 API 與 Agent 視窗拆分方式保留；API 使用本專案既有 OpenAI Responses，Agent 指本專案的受限工具迴圈。可調整已配置費率的模型、推理強度及每輪最多 1–5 次模型呼叫。不引入外部 Agent ID／Project ID、本地任意 API URL 或第二套 runtime；這些來源欄位不能在未接入的情況下假裝生效。金鑰只顯示是否已設定，仍由伺服器私密設定維護。

新聊天保存模型設定快照；已有快照的對話不被後續設定修改，升級前的舊對話保留原環境模型、low 與五輪。管理設定本身沒有批准 MES 寫入的能力。

模型及額度設定存於既有費用 SQLite 的 `ZZ_AI_AGENT_OPERATION_STATE`；其 `LOG` 保存操作者、時間與欄位前後值。額度是本次累計美元上限，取 UI 設定、部署上限與 US$20 的最小值。預留和額度修改使用同一資料庫交易；沒有歸零、月底清帳或刪除未知費用介面。此適配有別於參考版每月 Token 額度。

## 定時報告

使用者以可信登入建立屬於自己的限定模組報告，核對頻率、時間及設備後保存。這是持續的唯讀委託：可於瀏覽器關閉後執行；每次執行重新查核原 USER_SID／ACCOUNT_NO 仍啟用且保有模組 allowlist。暫停／刪除停止後續領取，已開始的唯讀查詢可完成。不是保存 Cookie、Token 或長效寫入簽章；不把委託身分回傳給前端。

直接沿用既有模組查詢，不呼叫模型，也不產生確認卡或業務寫入。前一日指 MES 時區的前一個**排程日期**，資料篩選依既有 `SCHEDULE_DATE／SHIFT_DAY`；不能將此快照稱為昨日實際報工事件總和。人工數量與 IoT 數量保留既有欄位，不把未知值補零。

每位使用者最多 20 份未刪除定義；每份報告最多 100 筆，超出範圍記錄失敗，不能把第一頁冒充完整報告。只有成功完成且資料完整才顯示報告。

使用既有作業 SQLite 的 `STATE` 保存 `report_schedule`／`report_run`，沒有 DB Schema 變更。服務 lifespan 啟動唯讀 worker，每 15 秒輪詢；以排程與原訂時間的雜湊在 SQLite 交易中唯一領取。重啟後不重跑已領取的時段；超過 15 分鐘才恢復的時段標為錯過，未完成的領取標為中斷。失敗／中斷不自動重試同一次報告。

自然語言解析是可驗證的有限格式：每天／週一至週五、24 小時時間、一個模組及可選 MC 設備編號，提供繁中、英文、泰文詞彙。模糊時間或多個模組／設備會要求改用明確表單；不是模型理解驗收。
