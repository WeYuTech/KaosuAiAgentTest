# ADR 006：對話串流與背景處理生命週期分離

日期：2026-11-03。狀態：待 PR #45 審查，尚未部署。關聯 #44；延續 ADR 005 的意圖、權限及版本契約。

## 來源與決策

既有 `app/main.py:process_message()` 負責 processing token、意圖分類、草稿版本及回覆保存；`app/model.py:invoke()` 負責費用預留與結算。保留這兩個邊界及原 JSON API，新增 SSE 傳輸，不另建可執行業務寫入的模型工具。

- 對話及首頁均增加 `/messages/stream`。首頁選擇串流而非輪詢步驟，以便分類後交接模組時沿用同一事件序列。
- 每次串流建立一個獨立背景執行緒。HTTP 串流只讀取事件；關閉 HTTP 不會呼叫停止，也不會撤銷處理 token。
- 工作、停止旗標及事件沿用 `STATE` JSON 的 `stream:v1:` 命名空間。完成／停止／失敗的步驟摘要寫入既有對話訊息 JSON；不新增資料表或欄位。
- 事件包含 `accepted`、`intent`、`step`、`delta`、`done`、`stopped`、`error`。`step` 由分類、模型、知識、資料查詢、草稿及確認卡的實際呼叫前後產生；不接受模型任意命名步驟。失敗及停止有各自狀態。
- 回覆片段取自 Responses 的 `response.output_text.delta`，最終回應及 usage 取自 `response.completed`。分類器的結構化 JSON 不送到前端。模型沒有回覆片段的固定卡控文案僅在最終回應呈現，不拆字模擬串流。[OpenAI 串流說明](https://developers.openai.com/api/docs/guides/streaming-responses)

## 停止與未知

`POST /api/streams/{id}/stop` 核對登入操作者與工作 token；已交接到模組時還核對對話 processing token。意圖由後端分類；選取範圍保持唯讀工具限制。

唯讀停止設定伺服器停止旗標，在工具邊界檢查；上游 Responses 串流另有停止監看，關閉上游連線。執行中的同步查詢會在安全邊界返回後停止，不中斷資料庫交易。確認停止後保存空回答與停止摘要，最後釋放鎖，不保留半成品答案。

寫入類訊息的停止不設定旗標，只回傳停止等待，原處理繼續。這裡的「寫入類」仍只能準備草稿／確認卡，實際 MES 寫入仍須原有人工確認端點。

瀏覽器斷線保留最後步驟及未知狀態，使用既有對話／入口回執讀回。只有新端點明確回傳未受理的 HTTP 404／405 才回退原 JSON 端點；收到 SSE 後不重送。舊服務沒有真實事件時只顯示一般等待提示。

費用沿用原帳本；上游串流中斷或未收到 usage 保留預留金額，標為 unknown。下游瀏覽器斷線但模型正常完成且收到 usage 時，依實際 usage 結算，不能將連線中斷當成免費。

## IIS 與限制

`configure_iis.ps1` 將 ARR 的 `responseBufferLimit` 設為 0，專用代理應用關閉動態壓縮，回應使用 `Cache-Control: no-cache`、`X-Accel-Buffering: no`。關閉動態壓縮也影響此代理應用的 JSON 回應；未更動原 MES 應用的壓縮設定。ARR 緩衝為伺服器層級設定，部署時需核對同機其他代理的影響。

此工作不是可在主機重啟後接續的持久化佇列。一般 HTTP 斷線已驗證；程序被終止、IIS 重啟及多程序壓力尚未驗證，不能把它們當成可自動重跑的情境。任何未知作業仍需查核，不能自動重送。

本次只在隔離環境驗收。正式 IIS、正式 MES 及真實模型的限制見 PR #45 與 `docs/design/issue44/驗收說明.md`。
